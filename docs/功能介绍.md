# 公司内部管理平台 —— 功能介绍

> 本文档用于系统介绍「公司内部管理平台」目前已实现与规划中的功能，帮助新加入的开发者或使用者快速了解项目全貌。

## 一、项目定位

这是一个面向中小企业的 **前后端分离内部管理系统**，目标是把公司日常运营中常用的几类工具整合到同一个平台里，包括：

- 公司信息与组织架构
- 员工信息管理
- 请假管理
- 报销管理
- 签到打卡
- 类 Jira 的项目看板与工单
- 类 Confluence 的知识库
- 站内邮件系统

系统采用统一的用户体系与权限模型，不同角色（员工 / 主管 / HR / 管理员）登录后看到的功能和数据范围有所不同。

## 二、技术架构

| 层面 | 技术选型 |
| --- | --- |
| 后端 | Python 3 + FastAPI + SQLAlchemy 2.0 + Alembic + PostgreSQL |
| 前端 | React 18 + TypeScript + Vite + Ant Design + React Router + Zustand |
| 认证 | JWT（Access Token + Refresh Token） |
| 接口风格 | RESTful，统一响应结构 `{ code, message, data }` |

后端按 `core / models / schemas / api / services` 分层：

- `core`：配置、数据库连接、JWT 与密码加解密、统一异常处理
- `models`：SQLAlchemy ORM 数据模型
- `schemas`：Pydantic 请求/响应校验模型
- `api/v1`：按业务模块拆分的路由
- `services`：具体业务逻辑

前端按 `api / store / router / layouts / pages` 分层，登录态由 `zustand` 管理，路由通过 `RequireAuth` 守卫未登录访问。

## 四、角色与权限体系

系统内置 4 种角色，可叠加拥有，超级管理员（`is_superuser`）拥有全部权限，不受角色限制：

| 角色代码 | 名称 | 说明 |
| --- | --- | --- |
| `admin` | 系统管理员 | 拥有全部管理权限，可管理公司信息、部门、员工账号 |
| `hr` | 人力资源 | 管理员工信息、部门、发布公告，审批请假 |
| `manager` | 部门主管 | 审批本部门请假、查看团队信息 |
| `employee` | 普通员工 | 基础功能权限，如查看信息、发起申请 |

权限校验通过依赖注入实现（`require_admin`、`require_hr_or_admin`、`require_manager_or_above`），在需要权限控制的接口上声明即可。

## 五、功能模块详解

### 1. 用户认证（已实现）

- 登录页对接真实接口，用户名 + 密码登录，返回 Access Token / Refresh Token
- axios 请求拦截器自动携带 Token；收到 401 时自动用 Refresh Token 换取新的 Access Token 并重试原请求，刷新失败才跳转登录页
- 获取当前登录用户信息（`/auth/me`），登录态持久化在 `localStorage`
- 修改密码（个人信息页内）

### 2. 组织架构（已实现）

- 部门支持树形结构（`parent_id` 自关联），可设置排序与部门负责人
- 「组织架构」页面左侧以 `Tree` 组件展示部门树（含人数、负责人），右侧为员工列表
- 支持部门新增 / 编辑 / 删除（新增编辑需 HR 或管理员权限，删除需管理员权限）
- 点击部门节点可筛选该部门下的员工

### 3. 公司信息与公告（已实现）

- 「公司信息」页展示公司名称、Slogan、简介、Logo、地址、官网、成立日期，管理员可编辑
- 公告栏展示所有公告（置顶公告排在最前），HR/管理员可发布、置顶、删除公告

### 4. 员工管理（已实现）

- 员工列表支持按部门筛选、按姓名/用户名关键字搜索
- HR/管理员可创建员工账号（含初始密码、部门、职位、角色等）、编辑员工信息、启用/停用账号
- 系统管理员可删除员工账号（超级管理员账号不可被停用/删除）
- 角色支持多选：系统管理员 / 人力资源 / 部门主管 / 普通员工

### 5. 我的信息（已实现）

- 展示当前登录用户的完整资料（用户名、邮箱、部门、职位、工号、入职日期、角色等）
- 支持自助编辑姓名、手机号、性别，并上传头像（图片保存在项目目录 `backend/uploads/avatars`）
- 支持修改密码（校验原密码、新密码二次确认）

### 6. 工作台 Dashboard（已实现）

登录后的首页，以卡片形式汇总真实数据：

- 待处理请假数（本人发起的、状态为待审批的请假单）
- 本月签到天数（当前自然月已打卡天数）
- 我的待办工单数（分配给自己且未完成的工单）
- 未读邮件数（收件箱中未读邮件数量）
- 下方展示公司最新公告列表

### 7. 请假管理（已实现）

- 员工可发起请假申请：选择请假类型（年假/病假/事假/调休/其他）、起止日期（自动计算天数）、原因
- 年假额度：每人每年 14 天；最多 5 天未休年假可结转至次年 3 月 31 日，到期仍有结转余额则自动清零。申请时优先扣减即将到期的结转年假，待审批与已批准的年假都会占用额度
- 「我的请假」列表可查看历史请假记录及状态（待审批/已通过/已驳回/已取消），待审批状态下可自行取消
- 主管/HR/管理员可在「待我审批」标签页查看下属提交的请假申请，填写审批意见后通过或驳回
- 审批通过/驳回后自动记录审批人与审批时间

### 8. 报销管理（已实现）

- 员工可发起报销申请：填写报销事项、费用类别（交通/餐饮/住宿/办公用品/通讯/其他）、金额、费用发生日期、说明
- 提交后可在「详情」中为报销单上传发票附件（支持图片 jpg/png/webp 或 PDF，最大 10MB），可填写发票号与发票金额，支持多张发票、上传前可删除
- 「我的报销」列表可查看历史报销记录及状态（待审批/已批准/已拒绝/已付款/已取消），待审批状态下可自行取消，且发票仅在待审批状态下可增删
- 主管/HR/管理员可在「待我审批」标签页查看下属提交的报销申请、查看发票原件，填写审批意见后批准或拒绝
- HR/管理员可在「待付款」标签页查看已批准待打款的报销单，确认付款后标记为「已付款」
- Dashboard 与顶部消息通知同步展示待处理/待付款的报销数量

### 9. 签到打卡（已实现）

- 首页卡片展示当天签到/签退状态，未签到显示「签到」按钮，已签到未签退显示「签退」按钮
- 「我的记录」标签页按月查看本人考勤记录（签到/签退时间、工作时长、状态）
- 「团队记录」标签页（主管/HR/管理员可见）按部门/人员查看团队考勤情况

### 10. Jira 风格看板（已实现）

- 支持创建项目（项目标识 Key、名称、描述），并添加/移除项目成员
- 进入项目后以看板形式展示工单，分「待办 / 进行中 / 已完成」三栏
- 工单支持标题、描述、类型（任务/缺陷/需求等）、优先级、状态、指派人、截止日期
- 「我的工单」聚合当前用户被指派且未完成的所有项目工单，用于 Dashboard 展示

### 11. Confluence 风格知识库（已实现）

- 支持创建知识库空间（空间 Key、名称、描述、负责人）
- 空间内页面以树形结构组织（支持父子页面），左侧目录树 + 右侧内容区
- 页面内容支持在线编辑与保存，记录创建人/最后更新人

### 12. 站内邮件系统（已实现）

- 支持撰写站内信、选择多个收件人、填写主题与正文
- 「收件箱」「发件箱」分标签展示，收件箱未读邮件有醒目标记
- 点击邮件查看详情自动标记为已读，支持删除邮件

### 13. 整合打磨（已实现）

- 顶部全局搜索框：输入关键字跨用户、知识库页面、项目、工单聚合检索，点击结果直达对应页面
- 顶部消息通知铃铛：聚合展示待审批请假数、待审批/待付款报销数、未读邮件数、待办工单数，定时轮询保持数据最新
- Dashboard 全面接入以上模块真实数据

## 七、如何启动本地环境

详细步骤见项目根目录 `README.md`，简要流程如下：

```bash
# 1. 启动本地数据库
cd backend && ./scripts/db_start.sh

# 2. 启动后端
source .venv/bin/activate
uvicorn app.main:app --reload --port 8000
# API 文档：http://127.0.0.1:8000/docs

# 3. 启动前端
cd ../frontend
npm install
npm run dev
# 访问：http://localhost:5173
```
