# 公司内部管理平台 —— 功能介绍

> 本文档用于系统介绍「公司内部管理平台」目前已实现与规划中的功能，帮助新加入的开发者或使用者快速了解项目全貌。

## 一、项目定位

这是一个面向中小企业的 **前后端分离内部管理系统**，目标是把公司日常运营中常用的几类工具整合到同一个平台里，包括：

- 公司信息与组织架构
- 员工信息管理
- 请假管理
- 签到打卡
- 类 Jira 的项目看板与工单
- 类 Confluence 的知识库
- 站内邮件系统

系统采用统一的用户体系与权限模型，不同角色（员工 / 主管 / HR / 管理员）登录后看到的功能和数据范围有所不同。

## 二、技术架构

| 层面 | 技术选型 |
| --- | --- |
| 后端 | Python 3 + FastAPI + SQLAlchemy 2.0 + Alembic + PostgreSQL |
| 前端 | React 18 + TypeScript + Vite + Ant Design + React Router + Zustand |
| 认证 | JWT（Access Token + Refresh Token） |
| 接口风格 | RESTful，统一响应结构 `{ code, message, data }` |

后端按 `core / models / schemas / api / services` 分层：

- `core`：配置、数据库连接、JWT 与密码加解密、统一异常处理
- `models`：SQLAlchemy ORM 数据模型
- `schemas`：Pydantic 请求/响应校验模型
- `api/v1`：按业务模块拆分的路由
- `services`：具体业务逻辑

前端按 `api / store / router / layouts / pages` 分层，登录态由 `zustand` 管理，路由通过 `RequireAuth` 守卫未登录访问。

## 四、角色与权限体系

系统内置 4 种角色，可叠加拥有，超级管理员（`is_superuser`）拥有全部权限，不受角色限制：

| 角色代码 | 名称 | 说明 |
| --- | --- | --- |
| `admin` | 系统管理员 | 拥有全部管理权限，可管理公司信息、部门、员工账号 |
| `hr` | 人力资源 | 管理员工信息、部门、发布公告，审批请假 |
| `manager` | 部门主管 | 审批本部门请假、查看团队信息 |
| `employee` | 普通员工 | 基础功能权限，如查看信息、发起申请 |

权限校验通过依赖注入实现（`require_admin`、`require_hr_or_admin`、`require_manager_or_above`），在需要权限控制的接口上声明即可。

## 五、功能模块详解

### 1. 用户认证（已实现）

- 用户名 + 密码登录，返回 Access Token / Refresh Token
- Refresh Token 刷新 Access Token
- 获取当前登录用户信息（`/auth/me`）
- 修改密码

### 2. 组织架构（后端已实现）

- 部门支持树形结构（`parent_id` 自关联），可设置排序与部门负责人
- 提供扁平列表接口与树形结构接口（`/departments/tree`）
- 部门的创建 / 更新 / 删除（需 HR 或管理员权限，删除需管理员权限）

### 3. 公司信息与公告（后端已实现）

- 维护公司基础信息：名称、Slogan、简介、Logo、地址、官网、成立日期
- 公司信息更新需管理员权限
- 公告支持发布、置顶、删除（需 HR 或管理员权限），所有登录用户可查看

### 4. 员工管理（后端已实现）

- 员工列表支持按部门、关键字筛选
- 员工详情查看
- 员工账号创建 / 信息更新（需 HR 或管理员权限）
- 员工个人资料自助更新（`/users/me/profile`）
- 员工账号删除（仅系统管理员）

### 5. 工作台 Dashboard（前端框架已搭建）

登录后的首页，以卡片形式汇总：

- 待处理请假数
- 本月签到天数
- 我的待办工单数
- 未读邮件数

目前展示的是占位数值，待对应业务模块开发完成后接入真实数据。

### 6. 请假管理（规划中 · 阶段2）

计划支持请假申请、多级审批流程、请假记录查询与统计。

### 7. 签到打卡（规划中 · 阶段3）

计划支持每日签到/签退、异常打卡处理、月度出勤统计。

### 8. Jira 风格看板（规划中 · 阶段4）

计划支持项目、看板、工单（Issue）的创建与流转，类似轻量版 Jira。

### 9. Confluence 风格知识库（规划中 · 阶段5）

计划支持知识库空间、文档树、富文本编辑与协作。

### 10. 站内邮件系统（规划中 · 阶段6）

计划支持公司内部用户之间的站内信收发、已读/未读状态管理。

### 11. 整合打磨（规划中 · 阶段7）

计划完善全局搜索、消息通知中心，并补充自动化测试。

## 六、初始账号

首次初始化数据（`python -m app.seed`）后会创建：

- 管理员账号：`admin` / `admin123`（请登录后立即修改密码）
- 默认角色：`admin`、`hr`、`manager`、`employee`
- 默认部门：`总部`
- 示例公司信息一条

## 七、如何启动本地环境

详细步骤见项目根目录 `README.md`，简要流程如下：

```bash
# 1. 启动本地数据库
cd backend && ./scripts/db_start.sh

# 2. 启动后端
source .venv/bin/activate
uvicorn app.main:app --reload --port 8000
# API 文档：http://127.0.0.1:8000/docs

# 3. 启动前端
cd ../frontend
npm install
npm run dev
# 访问：http://localhost:5173
```
