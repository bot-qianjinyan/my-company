# 部署指南

本文档介绍如何将「公司内部管理平台」从本地开发环境部署到远程服务器（生产环境）。

推荐使用 **方案一：Docker Compose 一键部署**，简单、环境一致、易于维护。如果服务器不支持 Docker，可参考 **方案二：传统部署（systemd + Nginx）**。

> 项目仓库已包含验证过的 `Dockerfile`、`docker-compose.yml` 等部署文件，可直接使用。

---

## 一、部署前准备

### 1.1 服务器要求

- Linux 服务器一台（推荐 Ubuntu 22.04 / Debian 12，2 核 4G 起步即可）
- 已开放 80/443 端口（如需 HTTPS）
- 有一个可以解析到该服务器的域名（非必需，也可直接用 IP 访问）

### 1.2 本地准备

- 一份可访问的 Git 仓库（GitHub/GitLab/自建 Gitea 等），或直接把代码打包上传到服务器
- 确认 `backend/.env` 中的敏感信息（数据库密码、`SECRET_KEY` 等）**不会**被提交到仓库（已在 `.gitignore` 中排除）

## 二、方案一：Docker Compose 部署（推荐）

### 2.1 架构说明

```
                    ┌─────────────────────────┐
用户浏览器  ──80──▶ │   frontend (Nginx)       │
                    │  - 提供前端静态资源       │
                    │  - /api/*    反代 → backend │
                    │  - /uploads/* 反代 → backend │
                    └───────────┬──────────────┘
                                │ 容器内部网络
                    ┌───────────▼──────────────┐
                    │   backend (FastAPI)      │
                    │  - 启动时自动执行数据库迁移 │
                    └───────────┬──────────────┘
                                │
                    ┌───────────▼──────────────┐
                    │   db (PostgreSQL 16)     │
                    │  - 数据持久化于 Docker Volume │
                    └───────────────────────────┘
```

前端与后端同源（都通过 80 端口的 Nginx 访问），无需处理跨域问题；发票等上传文件也由后端持久化到独立的 Docker Volume，容器重建不会丢失数据。

仓库中已包含以下部署文件，无需再手动编写：

| 文件 | 作用 |
| --- | --- |
| `backend/Dockerfile` | 后端生产镜像（Python 3.13 + Uvicorn） |
| `backend/docker-entrypoint.sh` | 启动前自动等待数据库、执行 `alembic upgrade head`、可选执行 seed |
| `frontend/Dockerfile` | 前端多阶段构建镜像（Node 构建 + Nginx 提供静态资源） |
| `frontend/nginx.conf` | Nginx 配置：静态资源 + `/api`、`/uploads` 反向代理 |
| `docker-compose.yml` | 编排 db / backend / frontend 三个服务 |
| `.env.production.example` | 生产环境变量模板 |

### 2.2 服务器安装 Docker

```bash
# 以 Ubuntu 为例，官方一键安装脚本
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER   # 将当前用户加入 docker 组，重新登录后生效
# 安装完成后确认版本（Docker 20.10+ 自带 compose 插件）
docker --version
docker compose version
```

### 2.3 上传代码到服务器

```bash
# 方式一：使用 git 拉取（推荐，便于后续更新）
git clone <你的仓库地址> my-company
cd my-company

# 方式二：本地打包上传（如果没有可访问的 Git 仓库）
# 本地执行：
#   tar --exclude='.venv' --exclude='node_modules' --exclude='pgdata' \
#       -czf my-company.tar.gz .
#   scp my-company.tar.gz user@your-server:/opt/
# 服务器执行：
#   cd /opt && tar -xzf my-company.tar.gz -C my-company
```

### 2.4 配置生产环境变量

```bash
cd my-company
cp .env.production.example .env
vim .env   # 或使用其他编辑器
```

**必须修改的 4 项配置：**

```bash
POSTGRES_PASSWORD=<设置一个强密码>
SECRET_KEY=<执行 openssl rand -hex 32 生成的随机字符串，用于 JWT 签名>
CORS_ORIGINS=https://your-domain.com   # 你的实际访问域名/IP（同域部署下影响不大，建议仍填写）
AUTO_SEED=true                          # 首次部署设为 true，自动创建管理员账号，之后可改回 false
```

生成随机密钥示例：

```bash
openssl rand -hex 32
```

如果服务器的 80 端口已被其他服务占用（如已有 Nginx/宝塔），可修改 `FRONTEND_PORT` 为其他端口，再由外层反代转发。

### 2.5 构建并启动服务

```bash
docker compose up -d --build
```

首次启动会：
1. 拉取 `postgres:16-alpine` 镜像并初始化数据库
2. 构建后端、前端镜像
3. 后端容器启动时自动等待数据库就绪 → 执行 `alembic upgrade head` 迁移 → 执行 `app.seed` 初始化数据（管理员账号 `admin / Weilai@123`，请登录后立即修改密码）→ 启动 Uvicorn

查看启动状态：

```bash
docker compose ps          # 确认三个服务都是 healthy
docker compose logs -f backend   # 查看后端日志（迁移是否成功等）
```

访问 `http://<服务器IP或域名>` 即可看到登录页。

### 2.6 常用运维命令

```bash
# 查看日志
docker compose logs -f backend
docker compose logs -f frontend

# 重启某个服务
docker compose restart backend

# 停止所有服务（保留数据）
docker compose stop

# 完全停止并删除容器（数据库数据仍保留在 volume 中）
docker compose down

# 彻底清除，包括数据库数据和上传文件（谨慎操作！）
docker compose down -v
```

### 2.7 更新部署（发布新版本）

```bash
cd my-company
git pull                       # 拉取最新代码
docker compose up -d --build   # 重新构建并滚动启动（数据库迁移会自动执行）
```

### 2.8 数据备份

**数据库备份：**

```bash
# 备份
docker compose exec -T db pg_dump -U mycompany mycompany_db > backup_$(date +%Y%m%d).sql

# 恢复
cat backup_20260731.sql | docker compose exec -T db psql -U mycompany -d mycompany_db
```

**上传文件（发票等）备份：**

```bash
docker run --rm -v my-company_backend_uploads:/data -v $(pwd):/backup \
  alpine tar czf /backup/uploads_$(date +%Y%m%d).tar.gz -C /data .
```

建议将以上两个命令写成脚本，配合 `crontab` 定时执行，并将备份文件同步到异地存储。

### 2.9 配置 HTTPS（可选，推荐生产环境启用）

最简单的方式是在服务器上额外用 Caddy 或 Nginx 做一层反向代理并申请 Let's Encrypt 证书，将 443 流量转发到 `docker-compose` 暴露的 `FRONTEND_PORT`（此时应将其改为一个非 80 的内部端口，例如 8088，避免与外层 Nginx 冲突）。

以 Caddy 为例（自动申请证书，配置极简）：

```bash
# /etc/caddy/Caddyfile
your-domain.com {
    reverse_proxy 127.0.0.1:8088
}
```

```bash
sudo systemctl reload caddy
```

## 三、方案二：传统部署（不使用 Docker）

适用于服务器已有既定运维体系、不方便安装 Docker 的场景。

### 3.1 环境依赖

- Python 3.11+（建议与本地开发一致的版本）
- Node.js 20+（仅构建时需要）
- PostgreSQL 14+
- Nginx
- （可选）`supervisor` 或 `systemd` 管理进程

### 3.2 安装 PostgreSQL 并建库

```bash
sudo apt install -y postgresql
sudo -u postgres psql -c "CREATE USER mycompany WITH PASSWORD '强密码';"
sudo -u postgres psql -c "CREATE DATABASE mycompany_db OWNER mycompany;"
```

### 3.3 部署后端

```bash
cd /opt/my-company/backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pip install gunicorn   # 生产环境建议用 gunicorn + uvicorn worker 管理多进程

cp .env.example .env
vim .env
# 修改 DATABASE_URL、SECRET_KEY、DEBUG=false、CORS_ORIGINS 等

# 执行数据库迁移
alembic upgrade head
# 首次部署初始化数据（创建 admin 账号等）
python -m app.seed
```

创建 `systemd` 服务文件 `/etc/systemd/system/mycompany-backend.service`：

```ini
[Unit]
Description=My Company Backend
After=network.target postgresql.service

[Service]
User=www-data
WorkingDirectory=/opt/my-company/backend
Environment="PATH=/opt/my-company/backend/.venv/bin"
ExecStart=/opt/my-company/backend/.venv/bin/gunicorn app.main:app \
    -k uvicorn.workers.UvicornWorker \
    --workers 2 \
    --bind 127.0.0.1:8000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

启动服务：

```bash
sudo mkdir -p /opt/my-company/backend/uploads
sudo chown -R www-data:www-data /opt/my-company/backend
sudo systemctl daemon-reload
sudo systemctl enable --now mycompany-backend
sudo systemctl status mycompany-backend
```

### 3.4 构建前端静态资源

```bash
cd /opt/my-company/frontend
npm ci
npm run build   # 产出 dist/ 目录
```

### 3.5 配置 Nginx

创建 `/etc/nginx/sites-available/mycompany`：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    root /opt/my-company/frontend/dist;
    index index.html;

    client_max_body_size 20m;

    location /assets/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8000/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /uploads/ {
        proxy_pass http://127.0.0.1:8000/uploads/;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/mycompany /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

### 3.6 配置 HTTPS

推荐使用 `certbot` 一键申请并自动续期 Let's Encrypt 证书：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

### 3.7 更新部署

```bash
cd /opt/my-company
git pull

cd backend && source .venv/bin/activate
pip install -r requirements.txt
alembic upgrade head
sudo systemctl restart mycompany-backend

cd ../frontend
npm ci && npm run build
sudo systemctl reload nginx
```

## 五、常见问题排查

**1. 容器一直重启 / 后端启动失败**

```bash
docker compose logs backend
```
常见原因：`.env` 中 `DATABASE_URL` 或数据库密码配置错误，或数据库尚未就绪（`docker-entrypoint.sh` 会自动重试 30 次，每次间隔 2 秒，超过则失败）。

**2. 前端能打开，但登录/接口报错（404 或跨域）**

检查 `frontend/nginx.conf`（或传统部署的 Nginx 配置）中 `/api/` 反代是否指向了正确的后端地址（Docker 内部为 `http://backend:8000/api/`，传统部署为 `http://127.0.0.1:8000/api/`）。

**3. 发票图片/PDF 无法访问**

确认 Nginx 是否配置了 `/uploads/` 的反向代理，且后端 `backend/uploads` 目录（Docker 下为对应 volume）中确实存在该文件。

**4. 忘记管理员密码**

可重新执行 `python -m app.seed`（不会覆盖已存在的账号），或直接连接数据库手动重置：

```bash
docker compose exec backend python - <<'PY'
from app.core.database import SessionLocal
from app.core.security import hash_password
from app.models import User

db = SessionLocal()
admin = db.query(User).filter(User.username == "admin").first()
admin.hashed_password = hash_password("新密码")
db.commit()
PY
```
