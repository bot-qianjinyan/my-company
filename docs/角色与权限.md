# 角色与权限

> 根据当前代码整理。角色定义见 `backend/app/seed.py`，接口校验见 `backend/app/api/deps.py`，前端判断见 `frontend/src/store/auth.ts`。

系统内置 **4 个角色**，保存在 `roles` 表。同一个人可以同时拥有多个角色，权限按并集生效。

另外还有用户表上的标记 `is_superuser`（超级管理员）。它不是角色，但接口校验时一律放行，前端也会把它当成同时具备 `admin`、`hr`、`manager`。初始账号 `admin` 同时带有这个标记和 `admin` 角色。

权限实际分成三档：

| 校验 | 放行角色 |
| --- | --- |
| `require_admin` | `admin` |
| `require_hr_or_admin` | `admin`、`hr` |
| `require_manager_or_above` | `admin`、`hr`、`manager` |

`employee` 没有单独的管理接口。只要登录，就可以使用基础功能。创建员工时如果没有选择角色，会默认加上 `employee`。

## 一、普通员工 `employee`

- 查看公司信息、公告、组织架构和员工列表
- 修改自己的姓名、手机、性别、头像和密码
- 发起、查看、取消自己的请假和报销，给自己的报销单上传发票
- 每日签到、签退，查看自己的考勤
- 创建项目和工单，查看全部项目；只能修改、删除自己负责的项目
- 阅读知识库
- 收发站内信、全局搜索

## 二、部门主管 `manager`

在普通员工能力之外，可以处理全公司的审批和团队考勤。审批和考勤范围是全部人员，不按本部门过滤。

- 查看、通过、驳回全部待审批请假
- 查看、批准、拒绝全部待审批报销，并查看发票
- 查看全部人员的团队考勤

## 三、人力资源 `hr`

包含主管的全部能力，另外可以管理组织和人事，以及报销付款。

- 新建、编辑部门
- 创建、编辑员工，分配角色，启用或停用账号
- 发布、置顶、删除公告
- 把已批准的报销标记为已付款

## 四、系统管理员 `admin`

包含人力资源的全部能力。下面这些操作只有管理员可以做。

- 删除部门
- 删除员工（超级管理员账号不能被停用或删除）
- 编辑公司信息
- 创建、编辑、删除知识库空间和页面
- 修改、删除任意项目（不限项目负责人）

## 五、超级管理员 `is_superuser`

这是用户表上的标记，不是第 5 个角色。接口校验时一律放行。初始账号 `admin` / `admin123` 带有这个标记。

## 六、公告

工作台「最新公告」和公司信息页的公告栏都是全员通知。列表署名是实际发布人的姓名（`created_by` 的显示名），没有发布人时显示「系统」。

| 操作 | 谁可以 |
| --- | --- |
| 查看公告 | 所有登录用户 |
| 发布、置顶、删除 | `hr`、`admin`（及超级管理员） |

部门主管和普通员工只能查看，不能发布。

公司里这类全员公告通常也由这两类人发：

- **人力资源**：放假安排、制度、入职离职、薪酬福利
- **行政 / 系统管理员**：办公通知、搬迁、门禁、系统变更

重大事项有时以公司或总经理名义发布，实际操作仍多由人事或行政代发。部门主管一般只发本部门通知，不会发到全员公告栏。
